Identifying Joins by Query Behavior
If you can't see the keywords directly, look at the results to infer the type of join:

Scenario									Likely Join Type
Only matching rows from both tables are shown					INNER JOIN or EQUI JOIN
All rows from the left table, unmatched right = NULL				LEFT JOIN
All rows from the right table, unmatched left = NULL				RIGHT JOIN
All rows from both tables, unmatched rows = NULL				FULL OUTER JOIN
Every row from one table combined with every row from another			CROSS JOIN
The table is joined to itself, often comparing rows in hierarchical data	SELF JOIN

1. Tables for All Queries

Employees Table:
employee_id	name		department_id
1		Alice		101
2		Bob		102
3		Charlie		NULL
4		David		104
5		Eve		105

Departments Table:
department_id		department_name
101			HR
102			IT
103			Marketing
104			Finance
---------------------------------------------------------------------------------------------------
2. INNER JOIN Example

Query:
SELECT e.name, d.department_name
FROM employees e
INNER JOIN departments d ON e.department_id = d.department_id;

Result:
name			department_name
Alice			HR
Bob			IT
David			Finance
Explanation:

Only employees with matching department_id in both tables are shown.
Charlie (no department) and Eve (department 105, no match) are excluded.
---------------------------------------------------------------------------------------------------
3. LEFT JOIN Example

Query:
SELECT e.name, d.department_name
FROM employees e
LEFT JOIN departments d ON e.department_id = d.department_id;

Result:
name		department_name
Alice		HR
Bob		IT
Charlie		NULL
David		Finance
Eve		NULL

Explanation:
All employees are shown.
Charlie and Eve have no department, so department_name is NULL.
---------------------------------------------------------------------------------------------------
4. RIGHT JOIN Example

Query:
SELECT e.name, d.department_name
FROM employees e
RIGHT JOIN departments d ON e.department_id = d.department_id;

Result:
name		department_name
Alice		HR
Bob		IT
David		Finance
NULL		Marketing

Explanation:
All departments are shown.
Marketing has no employees, so name is NULL.
---------------------------------------------------------------------------------------------------
5. FULL OUTER JOIN Example

Query:
SELECT e.name, d.department_name
FROM employees e
FULL OUTER JOIN departments d ON e.department_id = d.department_id;

Result:
name		department_name
Alice		HR
Bob		IT
David		Finance
Charlie		NULL
Eve		NULL
NULL		Marketing

Explanation:
Combines results from LEFT JOIN and RIGHT JOIN.
Shows all employees and all departments, with NULL where there's no match.
---------------------------------------------------------------------------------------------------
6. CROSS JOIN Example

Query:
SELECT e.name, d.department_name
FROM employees e
CROSS JOIN departments d;

Result: (25 rows = 5 employees × 4 departments)
name		department_name
Alice		HR
Alice		IT
Alice		Marketing
Alice		Finance
Bob		HR
Bob		IT
Bob		Marketing
Bob		Finance
Charlie		HR
Charlie		IT
...	...
Explanation:
Every employee is combined with every department, regardless of relationships.
---------------------------------------------------------------------------------------------------
7. SELF JOIN Example

Let’s modify the Employees table to include a manager:

employee_id	name	manager_id
1		Alice	NULL
2		Bob	1
3		Charlie	1
4		David	2
5		Eve	3

Query:
SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.employee_id;

Result:
employee	manager
Alice		NULL
Bob		Alice
Charlie		Alice
David		Bob
Eve		Charlie

Explanation:
The table is joined to itself to show who manages whom.
